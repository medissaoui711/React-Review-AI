# React Testing
Identify runner, environment, setup, scripts, mocks, and test naming. Map critical journeys to tests. Prefer behavior-focused React Testing Library queries by role/name and userEvent interactions. Cover loading, success, empty, validation, errors, async behavior, keyboard access, and boundary cases. Review mock isolation, cleanup, timers, deterministic fixtures, and network boundaries. Never infer coverage from file counts or claim tests pass unless a test runner actually ran and output was inspected.
